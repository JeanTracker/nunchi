# 눈치 안내

눈치는 Claude Code 세션 옆에 패널을 띄우는 플러그인입니다. 한동안 다른 일을 하다 세션에 돌아왔을 때 먼저 볼 것을 보여 줍니다. 에이전트가 나에게 묻는 것, 대화가 여기까지 어떻게 왔는지, 내 요청 중 아직 남은 것입니다. 그걸 읽고 답하고 이어 가면 됩니다.

패널은 분석 결과를 읽기만 합니다. 플러그인에 함께 실린 작은 엔진이 Claude Code 훅으로 세션마다 이벤트를 기록하고, 응답이 끝나면 새 턴을 `claude -p`로 뒤에서 분석합니다.

English: [docs/GUIDE.md](../GUIDE.md)

## 필요한 것

- macOS(애플 실리콘·인텔). 엔진은 맥용 실행 파일이라 파이썬이 필요 없습니다.
- Claude Code. 2.1.322~2.1.325에서 확인했습니다.
- Claude Code를 실행하는 셸의 PATH에 있는 `claude` 명령. 분석기가 새 턴마다 `claude -p`를 한 번씩 부르고 내 계정 사용량을 씁니다("분석 비용" 참고).
- 저장소가 비공개인 동안에는 마켓플레이스를 받을 때 그 저장소에 대한 git 권한.

## 설치

Claude Code 안에서 실행합니다. 마켓플레이스 등록과 플러그인 설치가 한 번에 됩니다.

```
/plugin install nunchi --marketplace JeanTracker/nunchi
```

터미널에서는 두 단계로 같은 일을 합니다.

```sh
claude plugin marketplace add JeanTracker/nunchi
claude plugin install nunchi@nunchi
claude plugin list                                   # nunchi@nunchi · enabled 가 보이면 됩니다
```

플러그인에는 패널, 세션을 `~/.claude-control`에 기록하는 훅, 엔진이 들어 있습니다. `~/.claude/settings.json`에 훅 항목을 넣지 않고(마켓플레이스와 켜 둔 플러그인은 Claude Code가 직접 적습니다), 대화에 더해지는 토큰도 없습니다.

Claude Code가 플러그인을 따로 받아 둡니다. 새 세션부터 붙고, 이미 열린 세션은 다시 시작합니다(`claude --resume <세션 ID>`). 훅은 세션이 시작될 때 읽히므로, 설치 전에 연 세션은 다시 시작해야 기록됩니다.

**갱신.** `claude plugin marketplace update nunchi` 다음 `claude plugin update nunchi@nunchi`를 하고 세션을 다시 시작합니다. 버전마다 폴더가 따로라서, 이미 열려 있던 세션과 돌던 분석은 옛 버전으로 끝까지 갑니다.

예전에 `~/.claude/skills/nunchi`로 복사해 두었다면 그 복사본은 지우세요(`rm -rf ~/.claude/skills/nunchi`). 설치된 플러그인이 앞서므로 복사본은 "이름이 이미 있음"으로 붙지 않습니다.

## 눈치 켜기

플러그인이 설치되어 있어도 모든 세션을 분석하지는 않습니다. 흐름을 보고 싶은 세션에서 `/nunchi`를 치면 그 세션이 분석 대상이 되고 패널이 열립니다. 그 뒤로는 응답이 끝날 때마다 분석되고, 세션을 다시 열어도 켜진 채로 남습니다. 켜기 전 응답은 다음 응답이 끝날 때 처음부터 한꺼번에 분석합니다.

켜지 않은 세션에서는 패널이 저절로 열리지 않습니다. 다시 끄는 명령(`/nunchi off`)은 아직 없습니다.

## 패널에 보이는 것

창이 110칸 이상이면 오른쪽에 창의 40% 폭으로 열립니다. 그보다 좁으면 입력창 위에 한 줄로 `눈치 목표: … · 묻는 것 n · 남은 것 n · #n 기준`이 보입니다. 아래는 위에서부터 차례로 설명합니다.

**머리 줄.** `눈치 · #12 기준`은 12번째 턴까지 분석한 결과라는 뜻입니다. 옆에 이런 것이 붙을 수 있습니다.

- `분석 대기...`, `분석 중...`
- `흐름 처음부터 만드는 중 #3/#12` 또는 `밀린 턴 반영 중`과 진행 정도
- `응답 2개 밀림`: 마지막 분석 뒤로 응답이 두 번 더 왔다는 뜻
- `분석 실패 · 이유`: 정해진 횟수만큼 다시 해 봅니다
- `자동 분석 꺼짐 · /nunchi로 켜기`: 옛 결과는 있지만 켜지 않은 세션

첫 결과가 나오기 전에는 `눈치 켜짐 · 다음 응답이 끝나면 분석합니다`가 보입니다.

**에이전트가 묻는 것.** 에이전트가 결정·확인·정보를 구하고 답을 기다리는 것입니다. 최근에 물은 것부터 번호, 한 줄 요약, 물은 턴, 에이전트가 한 말을 따옴표로 보입니다. `#5부터 답 없음`은 5번째 턴부터 답을 받지 못했다는 뜻이고, `일부 답함`은 일부만 답한 것입니다. 내 메시지가 답하면 닫힙니다. "권장대로 진행"처럼 앞 제안을 통째로 받아들여 닫힌 것은 `통째 승인으로 닫은 것`으로 따로 셉니다.

**지금까지.**

- `흐름`: 처음부터 지금까지 대화가 어떻게 흘러왔는지 한 덩어리로 정리한 글입니다. 분석기의 추정이라 흐리게 보입니다.
- `지금 목표`: 지금 다루는 대상과, 몇 번째 턴부터인지.
- `정한 것`: 내가 정한 것(✔).
- `방금`: 마지막 턴에 에이전트가 한 일의 요약.

**남은 것.** 아직 끝나지 않은 내 요청입니다. ○ 아직 다루지 않음, ◐ 진행 중(예: 병합을 기다리는 MR), ⊘ 못 했거나 미룸. 요청이 나온 턴이 함께 보입니다.

**번호 풀이.** 마지막 응답에 R17, §4.5, Phase 4c, 요구 이력 41 같은 기획 번호가 나오면, 프로젝트의 `docs/*.md`에서 찾아 원문을 5개까지 보입니다. 같은 꼴의 표와 제목으로 쓴 문서에서만 풀립니다.

패널의 링크(맨 주소, 마크다운 링크)는 클릭하면 열립니다.

## 분석 비용

켠 세션의 새 턴마다 `claude -p`를 한 번 부릅니다. 엔진이 세션 밖에서 부르므로 세션의 컨텍스트에는 더해지지 않습니다. 설정은 `~/.claude-control/config.json`에 둡니다.

```json
{
  "analyze_scope": "selected",
  "analyze_model": "",
  "analyze_workers": 1,
  "mod_width_ratio": 0.4
}
```

- `analyze_scope`: `"off"`면 분석을 모두 멈춥니다. `"all"`이면 켰든 안 켰든 모든 세션을 분석합니다. 기본값은 `/nunchi`로 켠 세션만(관제 화면을 쓰면 거기서 고른 세션도) 분석합니다.
- `analyze_model`: 분석에 쓸 모델. 비우면 `claude` 기본 모델입니다.
- `analyze_workers`: 동시에 돌릴 분석 수(1 또는 2). 같은 계정 사용량을 나눠 씁니다.
- `mod_width_ratio`: 패널 폭을 창의 몇 %로 할지(0.2~0.45).

여러 세션이 한꺼번에 응답을 끝내면 최근 응답부터 분석합니다. 엔진은 할 일이 있을 때만 뜨고, 대기열이 비면 스스로 끝납니다.

## 잘 안 될 때

- **패널이 채워지지 않는다.** 플러그인을 설치한 뒤에 시작한 세션인지, 그 셸에서 `claude`가 실행되는지 확인하세요. 오류는 `~/.claude-control/errors.log`에 남습니다.
- **세션 시작 때 엔진을 실행하지 못했다는 안내가 뜬다.** 플러그인을 갱신하거나 다시 설치하고(`claude plugin update nunchi@nunchi`) 세션을 다시 시작하세요.
- **amask와 함께 쓰기.** amask는 세션을 열 때 자기 훅과 mod를 덧붙입니다. 두 mod는 이름이 다르고 받는 이벤트도 겹치지 않습니다. 훅이 플러그인으로 옮긴 뒤 amask 아래 세션은 아직 확인하지 않았습니다.

## 지우기

```sh
claude plugin uninstall nunchi@nunchi
claude plugin marketplace remove nunchi
```

열려 있던 세션은 다시 시작하면 패널 없이 돌고 더 기록되지 않습니다. 세션 기록과 설정은 `~/.claude-control`에 남으니, 필요 없으면 그 폴더를 지우세요.

## 개발할 때

엔진은 러스트(`crates/engine`)입니다. main 브랜치에는 소스만 있습니다. 엔진을 `bin/`에 빌드하고 받아 둔 저장소를 세션에 붙입니다.

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
scripts/build-engine.sh
claude --plugin-dir ~/src/nunchi
```

설치된 플러그인을 먼저 지우세요. 둘 다 붙으면 이벤트가 두 번 기록됩니다. 엔진 시험은 `cargo test`입니다. 릴리스는 `.claude-plugin/plugin.json`과 같은 버전의 태그 `v<버전>`을 올려서 만듭니다. 그러면 워크플로가 엔진을 빌드해 마켓플레이스가 가리키는 `dist` 브랜치를 바꿉니다.
