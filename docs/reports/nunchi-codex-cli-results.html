실행 Sol · 독립 리뷰 Astra 6.2 · 2026.11.21

눈치 × Codex CLI

Codex CLI 0.169.0 대화와 눈치 엔진을 연결해 같은 터미널 창의 tmux 패널에서 분석 결과를 확인했다. 고정 대본의 의미 품질은 Astra 6.2의 판정에서 Sol 3회 중 2회가 다섯 기준을 모두 충족했다.

항목별 판정

실제 입력과 패널 표시 · 통과

Sol 대화에서 도구 호출과 중간 설명을 거쳐 나온 최종 답변을 사용자 요청과 한 턴으로 연결했다. 저장된 목표, SQLite 결정, CSV 질문을 Astra가 원문부터 패널까지 대조했다.

같은 프로젝트의 두 CLI · 통과

첫 세션은 할 일 API와 SQLite, 두 번째는 재고 API와 Redis로 진행했다. 독립 실행한 두 뷰어가 서로 다른 세션을 표시했다. 두 번째 세션은 제공한 런처로 실행했다.

Codex 단독 분석 · 통과

고정 3턴을 3회 재생했다. 성공한 분석 호출 9회 모두 gpt-6.2-sol이었고 Claude 호출은 0회였다.

결정 변경·요청 완료·질문 해소·결정 위반 · 각 3/3

세 번 모두 SQLite에서 PostgreSQL로 결정을 교체하고 CSV 완료를 기록했다. 답한 열 순서 질문을 닫았고 마지막 응답의 SQLite 사용을 결정 위반으로 감지했다.

현재 목표 유지 · 2/3

기준은 표현이 바뀌어도 현재 목표에서 상위 목적(할 일 API)을 식별할 수 있는지다. 한 회는 마지막 현재 목표에 CSV 내보내기만 남았다. 최초 목표는 세 번 모두 보존됐다.

Claude 대조군 · 각 3/3

동일한 대본을 Claude 원본 입력과 Codex 훅 입력으로 각각 3회씩 claude-opus-5-5에 재생했다. 다섯 기준 모두 통과했다. 한 실행에서는 별도 관찰 항목인 상위 API 요청까지 완료 처리했다. 한 대본에서 얻은 수치다.

실패 복구와 화면 갱신 · 통과

Astra가 분석기 종료 코드 42를 주입했다. 완료 턴 0을 유지하다 실제 Sol 재시도로 1턴이 저장됐다. 독립 뷰어 시험에서 파일 변경 후 표시까지 약 0.5초였다.

중단·중복 이벤트 · 통과

실제 CLI 작업을 중단한 뒤 완료 턴과 분석 호출 수가 유지됐다. 같은 Stop을 다시 전달해도 분석 결과가 중복되지 않았다.

CLI 재개 · 통과

다시 연 Codex가 원래 세션 ID로 연결됐고, 다음 분석을 기다리는 동안 마지막으로 성공한 SQLite 상태가 복원됐다. 재개 후 다음 턴까지 완료해 PostgreSQL로 변경된 결정과 CSV 열 순서를 패널에서 확인했다.

검증 범위 · 부분 검증

실험 환경은 macOS, tmux 3.8, codex-cli 0.169.0이다. 창 너비 155열 및 좁은 80열의 CLI와 패널을 사용했다. 일반 키 입력과 중단은 확인했다. 도구 실행 승인 키를 패널 갱신과 동시에 누르는 경우는 별도 검증하지 않았다.
