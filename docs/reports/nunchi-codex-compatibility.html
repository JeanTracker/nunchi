‘Codex 지원’은 세 가지 질문이다

대화를 분석하는 것, 분석에 GPT를 쓰는 것, Codex 내부에 화면을 그리는 것은 서로 다른 구현 과제입니다.

앞선 검토를 보완합니다. 데스크톱의 ‘내장 패널 경로가 없다’고 단정할 수는 없습니다. OpenAI는 thread entrypoint로 MCP 앱을 대화 옆 콘텐츠 탭에 노출하는 규격을 제공합니다. 다만 이것이 현재 눈치의 Claude mod 코드와 호환된다는 뜻은 아니며, Codex CLI의 터미널 패널 확장 API도 아닙니다. [S4]

가능: 공식 API 또는 기존 구현 근거 있음조건부: 환경 지원·새 구현·실증 필요미지원/불가: 명시한 현재 경로에서 성립하지 않음

‘가능’은 개발 가능성 판정입니다. Codex용 눈치가 이미 완성되었다는 뜻은 아닙니다. 문서에 없는 것을 모든 환경에서 영구적으로 불가능하다고 분류하지 않았습니다.

Desktop의 MCP 콘텐츠 탭 지원은 문서 근거가 있습니다. 특정 Codex 화면에서의 노출, 자동 세션 식별, 파일 접근, 탭 유지·자동 갱신은 이 조사에서 실행 검증하지 않았습니다.
‘패널 자체 불가능’은 아님

OpenAI는 MCP 앱을 대화 옆에 여는 공식 확장을 제공합니다. Claude의 JSX 패널은 웹 UI로 다시 만들어야 합니다.

탭 설치와 대화 수집은 별개

Thread entrypoint는 빈 인수로 호출됩니다. 앱이 전체 대화나 Codex의 로컬 thread ID를 자동으로 받는다고 가정할 수 없습니다.

자동 열기는 보장하지 않음

규격은 사용자가 탭을 여는 동작을 설명합니다. 응답마다 강제로 탭을 여는 동작이나 영구 고정까지 보장하지 않습니다.

[S4] [S6] 이 예상도의 색상·버튼·레이아웃은 설명을 위한 디자인이며 호스트의 정확한 UI를 재현한 것이 아닙니다.

기술 구성

공유할 엔진과 새로 만들 연결부

Codex의 입력과 출력 경계를 분리하면 Claude 기능을 유지하면서 확장할 수 있습니다. 대화 출처와 분석 모델도 따로 선택합니다.

설계 A · CLI부터 확장

별도 패널 + 공통 엔진

가장 명확한 경계의 확장안입니다. Codex의 내부 화면 API 없이 분석과 상시 표시를 함께 구현합니다.

  • Stop 훅이 선택한 세션의 작업을 큐에 적재
  • Codex 수집기가 요청·최종 응답·추가 입력을 Turn으로 변환
  • 기존 분석 파일을 새 TUI/웹 뷰어가 표시
  • 분석은 초기에는 Claude를 유지할 수도 있고, Codex 실행기를 추가할 수도 있음
설계 B · 데스크톱 통합

MCP 앱 + 대화 콘텐츠 탭

대화 옆에서 보는 UX에 가까운 공식 대안입니다. UI 표시 계약과 로컬 분석 데이터의 연결을 별도로 구현합니다.

  • MCP render 도구에 UI resource와 thread entrypoint 선언
  • 현재 Codex 스레드와 분석 대상 세션을 명시적으로 연결
  • MCP 서버가 결과를 제공하고 앱이 갱신
  • 목표 앱·계정의 탭 노출, 로컬 MCP·훅 배포를 먼저 실증

MCP 앱이 analysis.json을 직접 읽지는 않습니다. iframe은 앱 UI입니다. 로컬 파일 읽기는 권한을 가진 서버/브리지가 맡아야 합니다. 원격 MCP 서버는 설치만으로 사용자의 로컬 Codex 기록에 접근할 수 없습니다. [S6]

입력 어댑터

프로바이더·세션·턴 ID로 저장 공간을 구분하고, 원본 이력·중간 입력을 정규화합니다.

02 / ANALYSIS

실행기 분리

run_claude 호출부에 Codex 구현을 추가합니다. 분석 세션의 재수집·도구 사용을 통제합니다.

03 / VIEW

새 화면

CLI는 별도 뷰어, 데스크톱은 MCP 앱을 검증합니다. 접기·언어·복사도 각 UI에 구현합니다.

04 / REGRESSION

실세션 검증

압축·재개·중단·포크·추가 요청·질문창·다중 세션과 분석 품질을 확인합니다.

확인한 사실

코드를 읽고, 최소 입력으로 확인했다

기존 코드의 재사용 가능성과 즉시 호환되지 않는 부분을 확인했습니다. 실제 Codex 세션을 대상으로 한 자동 분석 시험은 수행하지 않았습니다.

기존 엔진 기준

PASS

Rust 워크스페이스 테스트

직전 검토에서 cargo test --workspace --locked 전체 통과. 이번 보고서는 동일한 커밋과 엔진 소스를 기준으로 합니다. Claude UI 시험이나 Codex 호환 시험을 대신하지 않습니다.

V1 · 합성 입력 시험

0 / 1

기존 파서의 턴 인식

동일 문구의 최소 샘플에서 Codex response_item 형식은 0턴, Claude user/assistant 형식은 1턴으로 읽었습니다. 실제 사용자 기록을 사용하지 않았습니다.

V2 · 훅 저장 시험

2개 누락

Codex 전용 정보 미보존

합성 Stop 입력에서 이벤트는 기록되지만 turn_id와 last_assistant_message는 현재 저장 목록에 없어 사라집니다. Codex 전용 필드를 보존하도록 바꿔야 합니다.

로컬 Codex 0.169.0에서 확인한 실행·프로토콜

codex exec --help에서 --ephemeral, --output-schema, --json, --output-last-message를 확인했습니다. 실제 모델 호출은 하지 않았습니다.

설치된 바이너리에서 생성한 TypeScript 스키마에는 thread/turns/list, thread/items/list, turn/completed, agentMessage.phase가 있습니다. phase는 commentary/partial_answer/final_answer 또는 null일 수 있습니다. null·이전 모델에 대한 처리가 필요합니다. [S9]

기능 목록에서 hooks와 plugins는 stable·true, tui_extensions_statusline은 under development·false입니다. 이 플래그만으로 ‘앞으로도 패널이 불가능하다’고 결론내리지는 않았습니다.

왜 transcript_path만 읽으면 충분하지 않은가

공식 문서는 훅 transcript의 내부 형식을 안정적인 인터페이스로 보장하지 않습니다. 기존 Claude 파서에 경로만 넘기는 방식은 합성 시험에서도 실패했습니다. 원본 파일 파서를 택하면 Codex 버전별 fixture가 필요합니다. App Server를 사용해도 동일한 스레드 저장소 접근, 페이지 전체 로딩, 세션 연결과 권한을 확인해야 합니다. [S1] [S2]

압축·포크·재귀 분석에서 필요한 검증

눈치가 이미 저장한 결정을 보존하는 것과 원문 전체를 처음부터 다시 읽는 것은 별개입니다. 과거 이력이 삭제되거나 접근할 수 없으면 완전 재분석을 보장할 수 없습니다. fork/rollback으로 과거 턴이 바뀌었을 때의 분석 지문 무효화도 필요합니다.

현재 Claude 실행기는 도구와 세션 저장을 끄고 CONTROL_TUI_ANALYZER=1로 자신을 제외합니다. Codex 실행기도 분석 세션을 다시 분석하지 않도록 동일 목적의 격리가 필요합니다. --ephemeral은 기록 저장 옵션이므로 도구 차단이나 훅 재귀 방지와 동일하지 않습니다. [R3]

아직 확인하지 않은 부분

Codex 실세션의 Stop 발화와 기록 저장 순서, 데스크톱 MCP 탭의 실제 노출, 자동 세션 식별, 패널의 실시간 갱신, GPT 분석 결과의 오탐·인용 정확도, Codex 환경의 압축·재개·포크·질문 답변 흐름은 미검증입니다. 이 보고서의 Codex 패널 그림은 출시 기능을 입증하는 화면이 아닙니다.
