현재 구조

Claude 경로는 플러그인 설치 후 /nunchi로 켭니다. Codex 경로는 작업 트리의 실험 구현으로, 별도 런처와 tmux 화면에서 검증했습니다.

플러그인만 설치하면 아직 기록되지 않습니다. 현 Codex 훅은 런처가 넘긴 CONTROL_TUI_CODEX_RUN과 그 폴더의 session-id에 의존합니다. 일반 codex 실행을 지원하려면 이 연결 방식을 바꿔야 합니다. Codex 훅 소스

첫 Codex 지원은 관찰 기능부터

사용자가 새 터미널 사용법을 배울 필요 없이, 기존 작업에 눈치를 붙이는 흐름입니다. 여기서 만든 세션 목록과 눈치 패널이 최종 관제 화면의 출발점입니다.

플러그인 설치Git 마켓플레이스에서 눈치 설치. 엔진 바이너리와 훅, 연결 안내 스킬을 함께 배포합니다.
훅 신뢰첫 연결 시 Codex의 /hooks에서 눈치 훅을 검토하고 신뢰합니다.
Codex 실행평소처럼 codex를 열고 새 작업을 시작하거나 저장된 작업을 재개합니다.
눈치에서 켜기로컬 화면에서 프로젝트와 세션을 선택해 분석을 켜고, 다음 완료 응답부터 결과를 확인합니다.

런처 밖에서도 세션 식별

SessionStart에서 세션과 프로젝트를 등록합니다. UserPromptSubmit과 Stop은 같은 세션·턴 ID로 결합합니다. 목록에 등록하는 정보와 분석을 켠 뒤 수집하는 요청·응답을 분리합니다.

공통 화면은 동일한 결과 읽기

로컬 앱이나 브라우저 화면이 세션 목록과 분석 결과를 읽을 작은 인터페이스를 둡니다. Claude와 Codex 모두 결정 사항 · 처리 결과 · 에이전트 질문 · 남은 요청이라는 기존 패널 용어를 사용합니다.

배포에서 확인한 범위 · CLI 0.169.0에 테스트 플러그인을 설치했고, .codex-plugin/plugin.json 형식에서 번들 훅이 신뢰 대기로 검색됐습니다. 실제 눈치 패키지의 설치부터 분석까지는 통합 시험이 남았습니다. 훅이 있는 패키지는 Git 마켓플레이스로 배포하고, 변경된 훅은 Codex가 재검토를 요구할 수 있습니다. OpenAI 패키징 문서

파일과 모듈별 변경 범위

영역현재첫 Codex 지원
분석 코어유지flow.rs가 공통 Turn으로 목표·결정·질문·요청을 분석합니다.같은 코어를 유지합니다. 품질 개선은 구조 개편과 별도로 검증합니다.
입력과 세션수정codex.rs와 transcript.rs에 입력 경로가 있습니다. 실험용 세션 ID 파일과 이벤트 파일명으로 연결을 구분합니다.등록 단계에서 공급자·세션 ID·프로젝트를 명시합니다. 세션별 켜기·끄기와 중복 방지는 엔진이 처리합니다. Codex의 훅 JSONL은 원문 사본을 남기는 구조이므로 저장 범위와 삭제 동작도 정해야 합니다.
분석기와 저장소폭 수정worker.rs에 run_claude와 run_codex가 있습니다. 두 경로 모두 analysis.json과 analysis_status.json을 씁니다.관찰 대상 공급자와 분석에 쓸 모델을 세션 설정으로 명시합니다. 기존 저장 경로는 그대로 읽고, 관제 목록은 공급자와 세션 ID를 조합해 조회합니다. 당장 전체 데이터를 이관할 필요는 없습니다.
배포Codex 산출물 추가scripts/make-dist.sh가 Claude 플러그인과 macOS·Linux용 엔진 바이너리를 묶습니다.동일한 빌드에서 Codex용 manifest, 훅, 스킬, 엔진을 담은 별도 플러그인 산출물을 만듭니다. 사용자는 Rust나 Python, tmux를 별도로 설치할 필요가 없는 구성을 목표로 합니다.
표시공통 조회 추가Claude Mod와 Python 실험 뷰어가 각각 결과 파일을 직접 읽습니다.Claude Mod는 유지합니다. 새 뷰어는 목록·분석 결과 조회 인터페이스를 사용합니다. 내부 디렉터리나 실험 런처 경로를 UI에 노출하지 않습니다.
작업 제어후속시험 범위는 턴의 기록·분석·표시입니다.관찰 기능을 먼저 출시합니다. 실행·응답·승인은 공식 실행 연결을 사용해 별도로 구현합니다.

처음 붙이는 사용자

  • 격리한 새 환경에서 설치하고 /hooks로 신뢰합니다.
  • 기본 codex를 실행합니다. 래퍼, tmux, 프로젝트 설정 직접 편집 없이 눈치 목록에서 세션을 찾습니다.
  • 세션을 켜고 응답 하나를 보내 실제 목표·결정이 표시되는지 확인합니다.

평소 작업을 계속하는 사용자

  • 같은 폴더에서 Codex 둘과 Claude 하나를 열어 결과가 해당 세션에만 붙는지 확인합니다.
  • 재개하면 같은 결과로 돌아오고, 분석을 끄면 새 원문 수집과 분석 호출이 멈추는지 확인합니다.
  • 훅 미신뢰·분석 실패·미연결 상태를 화면에서 판별할 수 있는지 확인합니다.
